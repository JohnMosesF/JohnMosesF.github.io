How I Approach Network Troubleshooting

A practical workflow based on my CCNA training and internship project experience with TCP/IP, VLANs, routing, DNS, and packet flow analysis.

JM

John Moses F

Network & Cloud Support Engineer

Start with the symptom

I first define what is failing: no connectivity, slow connectivity, DNS failure, wrong VLAN access, gateway issue, firewall restriction, or application port issue. A clear symptom prevents random configuration changes.

Use the OSI model as a checklist

Physical and Data Link

I check cable/link state, interface status, VLAN membership, trunk configuration, MAC learning, and switchport assignment.

Network Layer

I verify IP address, subnet mask, default gateway, route path, OSPF behavior if used, and whether the packet can reach the next hop.

Services

I confirm DHCP behavior, DNS resolution, firewall rules, and port availability. In cloud environments, I also check security groups, route tables, and VPC configuration.

Packet flow matters

Packet flow analysis helps connect the symptom to the root cause. I trace the path from source to destination, checking where the packet is dropped, misrouted, or blocked.

Document the fix

After restoring connectivity, I note the root cause and the configuration change. This helps prevent repeated issues and makes future troubleshooting faster.
